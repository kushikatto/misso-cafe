# Misooo Cafe — منوی دیجیتال

نسخه آماده اتصال به Supabase و انتشار روی GitHub Pages.

## قابلیت‌ها
- نمایش عمومی منوی منتشرشده بدون نیاز به ورود مشتری
- پنل مدیریت مخصوص حسابی که در جدول `profiles` نقش `admin` دارد
- ساخت، تغییر نام و حذف صفحه‌های منو
- افزودن، ویرایش و حذف محصولات و قیمت‌ها
- آپلود تصویر محصول (JPEG، PNG و WebP تا ۵ مگابایت)
- QR Code و کپی لینک منو
- طراحی واکنش‌گرا برای موبایل و دسکتاپ
- بدون سبد خرید و ثبت سفارش

## تنظیمات این نسخه
فایل `config.js` از قبل با آدرس پروژه Supabase و کلید عمومی publishable که برای این پروژه داده شده، تنظیم شده است. کلید publishable برای قرارگرفتن در فرانت‌اند طراحی شده است؛ هرگز `service_role` یا کلید secret را در این فایل قرار ندهید.

## یک مرحله باقی‌مانده در Supabase: فضای تصاویر
چون جداول و سیاست‌های اصلی را قبلاً ساخته‌اید، **نیازی به اجرای دوباره `supabase-setup.sql` نیست**.

1. در Supabase وارد SQL Editor شوید.
2. محتوای `storage-setup.sql` را اجرا کنید.
3. این کار فضای عمومی `menu-images` را می‌سازد؛ خواندن تصاویر برای مشتری آزاد است و آپلود/ویرایش/حذف فقط برای مدیر مجاز است.

اگر فعلاً تصویر نمی‌خواهید، این مرحله را می‌توانید بعداً انجام دهید؛ سایر قسمت‌های منو بدون تصویر هم کار می‌کنند.

## ورود مدیر
از دکمه «ورود ادمین» استفاده کنید و با ایمیل و رمز همان حسابی که در Supabase Authentication ساخته‌اید وارد شوید. برنامه نقش را از `profiles.role` می‌خواند؛ حسابی که `role = 'admin'` داشته باشد پنل مدیریت را می‌بیند. کاربران عادی فقط منوی عمومی را می‌بینند.

## انتشار در GitHub Pages
1. محتوای داخل پوشه `digital-menu-starter` را در ریشه یک GitHub repository بارگذاری کنید (خود پوشه را به‌عنوان ریشه سایت قرار ندهید، مگر اینکه تنظیم Pages را متناسب با آن انجام دهید).
2. در repository به مسیر **Settings → Pages** بروید.
3. گزینه **Deploy from a branch** را انتخاب کنید.
4. شاخه `main` و پوشه `/(root)` را انتخاب و Save کنید.
5. پس از انتشار، لینک سایت را باز کنید و QR Code را از همان لینک نهایی دریافت/چاپ کنید.

## تست پیشنهادی
1. سایت را در مرورگر باز کنید؛ باید صفحه‌های منتشرشده را نشان دهد.
2. با حساب مدیر وارد شوید؛ پنل مدیریت باید ظاهر شود.
3. یک صفحه آزمایشی و یک محصول آزمایشی بسازید.
4. در پنجره ناشناس یا مرورگر دیگر سایت را باز کنید؛ محصول منتشرشده باید بدون ورود دیده شود.
5. با یک حساب غیرمدیر وارد شوید (در صورت داشتن چنین حسابی)؛ نباید پنل مدیریت را ببیند.

## نکات
- اگر ورود مدیر خطا داد، وجود حساب در **Authentication → Users** و مقدار `profiles.role = admin` را بررسی کنید.
- اگر ساخت/ویرایش منو با خطای permission مواجه شد، سیاست‌های RLS جدول‌ها و نقش مدیر را بررسی کنید.
- اگر آپلود تصویر خطا داد، مطمئن شوید `storage-setup.sql` اجرا شده باشد.
- GitHub Pages فقط فایل‌های استاتیک را میزبانی می‌کند؛ داده‌ها و مجوزها از Supabase می‌آیند.
